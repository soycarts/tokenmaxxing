# Handover — 22 September 2026

From idea to a live product in one day. This is the record of what exists, what was decided and why, what is still open, and how to pick it up.

## What tokenmaxxing is

A zero-dependency CLI reads the local logs that Claude Code, Codex and Gemini CLI already write, prices every token at API list rates, and shows how much value a subscription delivered ("21.8× your plan price"). Optionally the user links the machine to tokenmaxxing.fyi and pushes hourly, daily or weekly token totals per model. The site shows a profile with a poster-style ROI card, embeddable SVG cards and badges, and opt-in leaderboards ranked by value, ROI, efficiency and volume, plus org boards.

Positioning: the incumbent (Token Tracker, tokentracker.cc, 39 tools, ~1.7k stars) tracks volume and reads OAuth tokens from the keychain. We rank by value, never read credentials, never edit tool configs without being asked, have no telemetry, and onboard by pasting one prompt into an agent. "Tokenmaxxing" had negative press in mid-2026 (Fortune, IBM, Pragmatic Engineer), so the brand is knowingly ironic and the volume board is labelled as such.

2. **Specs, then builds by agents.** `packages/cli/SPEC.md` and `apps/web/SPEC.md` are binding; CLAUDE.md says change the spec before the code. Two agents built CLI and web in parallel.
3. **CLI v0.1.** 30-day scan of 6.8k files in ~8s. `verify` matches ccusage to 0.00% on input and cache tokens. Deliberate divergence: Claude Code writes one message as several lines with cumulative usage; ccusage keeps the first line, we keep the largest (verified by hand on a raw log: 6.8k vs 81.9k output tokens in one file). Output is therefore ~1.9× ccusage's figure and correct.
4. **Infra.** Supabase project created via Management API; GitHub repo created; Vercel linked; domain attached; auth redirect list set via API. Classifier blocked Claude from `vercel env add`, `vercel deploy` and creating Supabase auth users, so Carter runs those.

## Decisions worth remembering

- npm name `tokenmaxxing` belongs to anaclumos (account switcher, 1.4k weekly downloads). We ship `tokenmaxxing-cli`. Options if the bare name matters: ask for a transfer, or register an npm org `tokenmaxxing` and publish `@tokenmaxxing/cli`.
- Prices come from LiteLLM (has Anthropic's 1h cache-write rate) and models.dev (had GPT-6 and Gemini 3.x first), locked into the CLI at publish time and seeded into `model_prices` so site and CLI agree. `overrides.json` beats both. Unknown models are never silently $0. Vendors publish no pricing API; a weekly human-page research routine was proposed and parked.
- Site aggregates only over public profiles for the sponsor audience line; the privacy policy allows published aggregates only over groups of ≥ 20 people.
- Org tier subscriptions and data reports are parked. Sponsored spots are a scaffold. Keep the OSS in soycarts/tokenmaxxing; commercial code goes into the bountify-ai GitHub org when it exists.
- Privacy policy and terms name Bountify, Inc. as controller/operator, are in force from 22 September 2026 under Delaware law, and are checked by Carter. The site reads the effective date from the document's first line; there is no env flag.

## How to operate

- Deploy: `cd apps/web && vercel deploy --prod --yes` (Carter only; Claude sessions are blocked from deploying).
- Apply schema/prices to the live DB: via Management API `POST /v1/projects/iitzmnrocuepimnhbkth/database/query` with the whole idempotent `apps/web/supabase/schema.sql`, then `seed_prices.sql` (see `docs/LAUNCH.md`).
- Add a sponsor: insert into `sponsors` with `placements`, `starts_at`, `ends_at`, `active = true`.
- Local dev: `apps/web/.env.local` has the live keys; `npm run dev` on port 3020. Never insert test data into the live DB from dev.
- CLI from a checkout: `node packages/cli/dist/cli.js <cmd>`; `TOKENMAXXING_HOME=/tmp/x` for a scratch home.
- Emails referenced by the site: `privacy@`, `legal@`, `sponsors@tokenmaxxing.fyi`; all three forward (set up by Carter).

## Last two builds

### Pricing automation (`docs/PRICING.md`)

- `.github/workflows/pricing.yml` runs daily at 06:00 UTC: refreshes the LiteLLM and models.dev snapshots, regenerates `apps/web/supabase/seed_prices.sql`, and opens or updates one PR on `pricing/auto` with a markdown diff from `packages/cli/scripts/pricing-diff.mjs` (changed rates, added, removed).
- `.github/workflows/pricing-apply.yml` applies `seed_prices.sql` to the live DB on push to main when it changed. Needs repo secrets `SUPABASE_ACCESS_TOKEN` and `SUPABASE_PROJECT_REF`, and "Allow GitHub Actions to create and approve pull requests" in repo settings. `ci.yml` runs build + tests on every push and PR.
- Bugs it caught: the refresh script was dropping Anthropic's 1-hour cache-write rate; 62 retired model ids would have become unpriced (now retained at last price, tagged `retained_since`); Vertex AI entries poisoned the fuzzy match; `SNAPSHOT_DATE` changed daily. Tests that would have blocked legitimate price changes were rewritten to test the maths on an inline rate table.
- Rules: overrides that set a price must cite a `source` URL and `added` date. A model listed at $0/$0 upstream is unpriced ("listed at $0 upstream") unless another entry or an override prices it; the seed deletes stale $0 rows. Live `model_prices` has 1,010 rows.
- Today's OpenAI cut (GPT-6 Sol $2/$10, Luna $0.10/$0.50) is already in both upstreams; no override needed.
- Known behaviour: prices are not dated, so a cut reprices all history. A dated price table is a future improvement.
- A weekly cloud research routine reading vendor pages was designed and parked (claude.ai needs GitHub connected first; Carter chose not to build it for now).

### Several plans per provider (`docs/specs/multi-plans.md`)

- Plans are now lines with quantities: `{ "claude": [{ "plan": "max-20x", "qty": 5 }, { "plan": "pro", "qty": 1 }] }`, plus custom lines `{ "plan": "custom", "label", "monthly" }`. Legacy `{ "claude": "max-20x" }` is read forever by CLI, site and SQL.
- Plan table refreshed 2026-09-22: Claude pro/max-5x/max-20x/team-standard/team-premium; ChatGPT go/plus/pro-100/pro/business; Cursor pro/pro-plus/ultra/teams; Google ai-plus/ai-pro/ai-ultra-100/ai-ultra. Sources listed in `packages/cli/src/plans.md`.
- CLI: `plan add|set|remove`, `x5` or `--qty`, `plan list` with totals, report shows one ROI line per provider plus a total. Site: `/me` rows with add/remove (works without JS), poster caption "5× Max 20x + 1× Pro", `/api/v1/u` returns `plans` and `plans_monthly_usd`. SQL `plans_monthly_usd` handles both shapes; applied live and verified.
- **Decided 2026-09-23:** the ROI board ranks only users whose plans total ≥ $20/month; profiles and badges still show ROI for any plan; value board unaffected. Applied live.
